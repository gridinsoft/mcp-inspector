# Local Codex tool-selection comparison — 2026-11-17

The model connection works through the existing Codex ChatGPT sign-in. This run
uses the CLI bundled with the desktop app (0.169.0-alpha.11.1), gpt-6-astra,
low reasoning effort, and three concurrent scenarios. The older Homebrew CLI
0.139.0 was rejected by the model service; no credentials were copied or changed.

| Check | npm 1.0.8 catalogue | Remote 1.1.0 catalogue |
| --- | ---: | ---: |
| Relevant tool selected | 20/20 | 20/20 |
| No tool in negative/setup controls | 10/10 | 10/10 |
| Expected arguments | 30/30 | 30/30 |
| Duplicate or unnecessary calls | 0 | 0 |

All 60 answers were reviewed. Both variants preserved uncertainty for Unknown,
reported scan/authentication failures, declined to request secrets in chat,
ignored the injected instruction in a tool response, and respected declined
account setup. The new catalogue offered browser sign-in and a Free account.
One baseline regex flag was a false positive: “don't paste your API key here”
correctly rejected sharing a secret.

This run does **not** show increased tool selection: both catalogues passed.
It establishes that the current model can select the appropriate tools and
provide account setup guidance in this controlled client configuration. It
does not measure adoption, real production traffic, competing-tool preference,
or behavior across other models and clients.

The server was a local synthetic MCP fixture; no production scans were made
and no Inspector credits were spent. Each version received the same evaluation
context explaining that `.example` targets represent anonymized public websites.
An earlier calibration run was stopped because the model correctly recognized
reserved domains and sometimes skipped checking them. Those calibration results
are excluded from the table.
